# Farm Watch presentation roles v1

## Purpose

Farm Watch uses one evidence and science pipeline, then presents that evidence differently by authenticated account role. Presentation must not change the underlying observations, derived products, scientific relationship applicability, uncertainty, or authorization boundary.

## Roles and presentation profiles

| Account role | Presentation profile | Intended use |
| --- | --- | --- |
| `owner` | `technical` | Current owner/developer experience: raw evidence, diagnostics, QA controls, provenance, fine materializations, and technical interpretation. |
| `admin` | `technical` | Future trusted administrators who need the same analytical presentation as the owner. The role remains distinct from `owner`; technical presentation does not by itself grant owner-only account-management authority. |
| `viewer` | `guided` | Human-readable interpretation derived from the same supported evidence, with technical implementation detail suppressed by default. |

Unknown roles fail closed.

## Guided viewer contract

Viewer presentation should answer practical questions in ordinary language: what is known, what it means at the supported level, how current or uncertain it is, and what remains unknown.

The guided profile must not:

- convert neutral physical evidence into deer use, bedding, movement, concealment, habitat quality, attraction, stand suitability, or management recommendations unless an explicitly authorized deer relationship supports that interpretation;
- convert modeled or proxy evidence into an observation;
- hide material uncertainty or stale/unavailable state;
- expose raw fine-grid artifacts that the server presentation policy marks `summary_only`;
- rely on browser-only hiding as an authorization control.

Technical provenance can be retained behind intentionally secondary detail surfaces, but the default viewer experience should not require understanding grid encodings, hashes, algorithm versions, raster observation counts, packed arrays, QA diagnostics, or internal experiment terminology.

## Technical profile contract

Owner and admin accounts retain the current evidence-heavy interpretation: raw materialization access where otherwise authorized, scientific/QA diagnostics, technical evidence tables, provenance, and fine-map capabilities.

This is a presentation profile, not a second science pipeline. Both profiles must remain bound to the same canonical evidence, source identities, freshness rules, interpretation boundaries, and deer-science relationship registry.

## Server enforcement

`farm-watch-materialization` enforces viewer artifact restrictions before private Storage download. Client presentation is not a substitute for that boundary.

`farm-watch-private` reports the normalized account role and the presentation capabilities generated by `farm-watch-presentation-policy.ts`. The browser must branch from those server-issued capabilities rather than infer privilege from email, local state, or UI controls.

## Evolution rule

New Farm Watch presentation features should declare whether they are technical-only, guided-safe, or shared. New account roles must map explicitly to a presentation profile; do not silently inherit owner behavior.
